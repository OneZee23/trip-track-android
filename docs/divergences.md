# Where Android differs from the iPhone app

Every intentional difference is listed here with its reason. Anything not listed is expected to
behave exactly like the iPhone app.

| Area | Android | iPhone | Why |
|---|---|---|---|
| Test application | Robolectric uses a lazy test graph, skips recording/auth/backfill startup and cancels owned work on termination | XCTest uses the AppBootstrap service-start seam | Robolectric recreates Application within one JVM; process-lifetime jobs must not escape into the next test. Production still starts all services |
| Screenshot verification | Roborazzi compares Mac baselines locally by default; Linux CI runs the rendering tests with `-Proborazzi.test.verify=false` | XCTest screenshots on the canonical iPhone simulator | macOS and Ubuntu render fonts/shadows differently; baselines are recorded and verified on the Mac |
| Purchases | No in-app purchases at launch; PRO is hidden like in the iOS Russian storefront | StoreKit PRO and tips | Google Play pays nothing to a payout bank in Russia (Dec 2024) |
| Sign-in | Google only | Sign in with Apple only | Owner decision 30 Oct 2026: separate accounts per platform for now |
| Background location disclosure | Android-only copy names collection of precise location for automatic start/route recording even when closed or not in use, before the native permission/settings step, in all 13 languages | iPhone explanation refers to background access, a minimized app or locked screen | Google Play requires a prominent in-app disclosure before permission access. Both onboarding and recording use generated overrides from `tools/strings/android.json`; permission sequencing is unchanged |
| Domain representations | GeoPoint, UUID, Instant; associated enums use sealed types | CLLocationCoordinate2D, UUID, Date, associated Swift enums | Pure JVM domain types; JSON shapes and units stay the same |
| Snapshot equality | Kotlin data class equality, including TripRouteLocator.Fix; compare ByteArray contents explicitly | Trip and map models use selective SwiftUI equality; route Fix compares only its index | UI diffing optimizations belong to the Android presentation layer |
| Model initialization | Currency is supplied explicitly; unconfigured fallback is € | Vehicle reads FuelCurrency.current from UserDefaults | Keep settings access outside pure JVM domain types |
| Places sort spelling | Kotlin entry `PlacesSort.byName`, raw/JSON value `name` | Swift case `PlacesSort.name` | Kotlin enums inherit a `name` property; persisted values stay the same |
| Place history queue | An ordered JSON array of UUID strings in SharedPreferences, committed on IO under `places.pendingHistory` | A typed string array in UserDefaults under the same key | SharedPreferences has no ordered array type; the key, ID values, deduplication and drain points stay the same |
| Place runtime execution | Room reads/writes on IO, geometry on Default, committed changes through Room invalidations | Background detail reads and geometry; view-context writes and NotificationCenter on MainActor | Room owns its transaction executor and change delivery; no database work belongs on Android's main thread |
| Place checkpoint focus | Compose scroll relocation reveals the checkpoint row, with a 1,400 ms highlight; target consumed for the screen's life | SwiftUI `scrollTo(anchor: .center)` with a spring and the same highlight duration | Compose owns the scrolling viewport and relocation animation; the chosen checkpoint and one-time focus are preserved, while its exact alignment follows the native relocation |
| Checkpoint geocoder | Android Address locality, subLocality and featureName | CLPlacemark locality, subLocality and name | The same fallback order uses the platform geocoder; provider data and returned names can differ |
| Recording boundary application | `Trip.withRecordingBreaks` in core:logic normalizes breaks and annotates points; recording uses it, and metric calculations derive indices before filtering | Trip initialization and the recordingBreaks setter do this automatically | core:model cannot depend on core:logic; storage adapters must call the helper after decoding/loading and when replacing breaks |
| Location/time representation | Immutable LocationFix and Instant; non-finite timestamps cannot be represented | CLLocation and Date; continuity/normalization reject non-finite dates | Pure JVM recording math; unknown measurement fields retain -1 |
| Geodesic distance | WGS84 inverse iteration; spherical fallback only when the iteration does not converge near antipodes | CLLocation.distance(from:), whose implementation is supplied by Apple | CoreLocation is unavailable on the JVM; the port passes the unchanged iOS distance tolerances, but does not promise bitwise equality with Apple's distance implementation |
| Badge metadata | Pure `BadgeRule` catalogue in core:logic; UI resolves words and art by ID | Badge combines metadata, SwiftUI Color and unlock predicate | Keep award rules independent of Android UI and generated string resources |
| Credential storage | Android Keystore AES-256-GCM key, credential-encrypted AtomicFile in noBackupFilesDir; package + API host scope | AfterFirstUnlockThisDeviceOnly Keychain items | Native Android protection, no backup or device transfer; locked/corrupt/unreadable storage returns unavailable |
| Credential writes | One encrypted snapshot commits tokens and session markers together; write failures propagate | Keychain updates each item separately; TokenStore suppresses save errors | Preserve the prior pair when encryption or writing fails and prevent reporting an unpersisted rotation as recovered |
| Session identity | Successful login's backend account UUID identifies the account | Apple credential subject plus backend account UUID | Google proof is verified by the server; the client does not trust locally decoded token claims |
| Legacy credentials | No migration from the historical iOS Keychain service | Copies legacy Keychain items into app/host scope | Android has no previous Keychain installation or transferable session |
| HTTP transport | OkHttp HTTP/1.1 and HTTP/2; cancellable coroutine calls | URLSession can also choose HTTP/3 | The selected Android network stack has no HTTP/3 transport |
| Network failures | EOF/reset maps to connectionLost; socket timeout to timedOut; connect failure to cannotConnect; DNS/no-route to offline | URLError has platform-specific error codes | Preserve retry classes with the exceptions Android exposes; DNS/no-route cannot distinguish offline from an unavailable host |
| Redirects | API and photo redirects fail with their HTTP status | URLSession follows redirects | Prevent forwarding x-access-token or bypassing the photo host allowlist on a redirected destination |
| Diagnostic logs | Mask sensitive values with a bounded linear scan; URLs lose IDs/query; response logging contains only status | APILogger uses regex and includes response previews | Java regex over long escaped strings can overflow its stack; status-only responses avoid logging server content |
| Me response encoding | bioProvided stays local; an explicitly cleared bio round-trips as null | Synthesized Swift response encoding can include its local presence flag | Follow docs/api-contract.md's explicit rule that the presence flag is never a wire key; Me is a response, not an outgoing account patch |
| Polyline preview cache | Synchronized access-order cache, at most 200 trips | NSCache with countLimit 200 and system memory-pressure eviction | NSCache is unavailable on the JVM; coordinate values and explicit invalidation are preserved |
| Places text comparison | Locale-aware JVM case folding, Unicode normalization and JDK Collator | Foundation case/diacritic-insensitive search and localizedCaseInsensitiveCompare | Foundation is unavailable on the JVM; platform Unicode/collation tables can differ. The port keeps stable ties and the iOS fixtures |
| Geo presentation dependencies | Callers supply resource formatters/checkpoint words, locale, ZoneId and persisted sort raw value | AppStrings, LanguageManager, Calendar and UserDefaults | core:logic is pure JVM; translations and settings stay in their owning adapters |
| Atlas loading | Immutable JVM snapshot from synchronous `RegionAtlas.loadBundle()`; lazy shared fallback | `loadIfNeeded()` parses off-main and publishes through MainActor | Pure JVM module has no UI dispatcher; the map/data adapter must load on its worker thread |
| Fog geometry types | Coordinate runs and Double `MapPoint`/`MapRect`; grid input uses a 2^28-unit Mercator world | MKMultiPolyline, MKMapRect and CoreGraphics | Native paths and projection conversion belong to core:map; widths and grid constants remain unchanged |
| Journal presentation | Explicit Locale, ZoneId, localized-region callback and precomputed historical levels; JDK month formatting | LanguageManager, Foundation Calendar/DateFormatter and library-side TripLevelHistory | Keep translation, settings and award calculation outside these builders; platform Unicode/date tables can differ |
| Units and policy dependencies | Callers supply `MeasureWords`, `ProWords`, date formatting, current time, ZoneId, WeekFields and badge ledger; functions return the next ledger | AppStrings, LocalizedDateFormatter, Calendar.current, Date() and UserDefaults | core:logic stays pure JVM; the app adapters preserve the same language, calendar and persisted values |
| Measurement number formatting | Frozen Foundation grouping separators and minimum grouping digits for the 13 languages, with Swift rounding | UnitNumber uses Foundation NumberFormatter and rounded() | JVM and Android locale tables differ; frozen Swift fixtures preserve the iPhone output |
| String and date adapters | AppStrings instance with a chosen-language Android configuration context; cached Android ICU date formatters, Instant and explicit ZoneId; pricePerLiter takes the currency | Static AppStrings functions with LanguageManager.Language, Foundation DateFormatter/Date and FuelCurrency.current | Android resources and native date APIs; settings stay with the caller. SDK 35 matches the Swift string/date fixtures in all 13 languages; other OS versions can ship different ICU tables |
| Badge metadata | Color and unlock callback are deferred | Badge combines metadata, SwiftUI Color and unlock predicate | Design and award rules belong to their owning modules |
| Store baseline | Room schema version 1 is Core Data model v24; no migration history | 24 Core Data versions with lightweight migrations | Android starts at today's model; later changes are new Room versions with migrations |
| Column types | UUID as lowercase text, dates as `Long` nanoseconds (saturating outside the years 1677 to 2262), optional scalar attributes `NOT NULL` with the model default | UUID and Date attributes; optional scalars read as plain `Double`/`Bool`/`Int` | SQLite has no UUID/date type; nanoseconds round-trip exactly, which the manual-track guard needs; iOS code can never see NULL in a scalar |
| Hidden keys | `pk` column on VisitedGeohash, GeocodeCache, Road, RevealedCell; `tripOrder` on photos and checkpoints | Core Data's hidden `Z_PK` and ordered-relationship positions | Room needs the primary key and the relationship order spelled out |
| Index names | Prefixed with the table (`TripEntity_byStartDate`); `byId` is the primary key; `byKey` plus its uniqueness constraint is one unique index | Fetch index names scoped to an entity | SQLite index names are global to the database |
| Commits | Every repository write commits on return; a pull is wrapped in `batch {}` instead of `flushPendingApplies()` | `applyRemote*` defer the save to one flush | Room writes in transactions; the batch keeps one commit per pull |
| Store notifications | Repositories hand sync work to `SyncRequestSink`; no `.tripPhotosChanged`/`.discoveriesChanged` posts | NotificationCenter posts after saves | UI observes Room; the queue lives in `core:sync` |
| Adding a trip photo | The trip is checked before the JPEG is written | The file is written first | iOS left an orphan file when the trip was gone; nothing else changes |
| Geohash in stores | Stores take geohash keys or a `GeohashOf` encoder | Stores call `GeohashEncoder` | The encoder belongs to `core:logic`, ported in parallel |
| Sync persistence | Account/API/store-scoped AtomicFile snapshot keeps pending, in-flight and failed operations; Room flags are also recovered on each pass | Queue is in memory; pending entities are recovered on startup | Task requires restart persistence, including deletes whose local row is already gone and the five-failure cap |
| Manual sync retry | Clears the error and resets retryCount to zero | Current retryFailedNow clears only lastError | Requested manual retry must reopen the automatic retry budget |
| Sync concurrency | Acknowledgements keep newer trip/journey/settings edits pending; batch removes operation IDs from its sent snapshot; cancelled retry snapshots cannot restore operations | Vehicle acknowledgements have a timestamp guard; other paths have fewer race guards | Preserve pending local edits and durable cancellation while Room/coroutines run concurrently |
| Sync store identity | Singleton UUID in a sync-owned SQLite metadata table, separate from Room's domain schema | Core Data NSStoreUUIDKey | Room's identity hash identifies the schema, not a particular database; replacement must force a full pull |
| Sync scheduling | WorkManager: 15-minute periodic work, connected-network constraint, exponential backoff starting at 10 seconds; local wake-ups coalesce for 250 ms; foreground timer remains 300 seconds | Foreground/network notifications and a 300-second timer; queue backoff is 2^retryCount seconds | Android persistent-work limits; queue backoff and five-failure cap are retained |
| Connectivity | ConnectivityManager default-network snapshot/callbacks require validated internet; Wi-Fi is reported only on that path | NWPathMonitor reports a satisfied path and its interface | Native Android connectivity API; avoid treating a captive portal as usable internet |
| Sync events and owners | SharedFlow carries appliedTripIds; AppGraph supplies profile sync, settings reload, cache invalidation and vehicle preference cleanup | NotificationCenter and shared service instances | Keep feature ownership and explicit dependencies; profile identity still runs with Cloud Sync off |
| Photo raster encoding | Android pixel renderer/JPEG codec, same 200/50 and 1440/70 limits; original variant always uses the bounded clean raster | UIKit/ImageIO; may choose a smaller stored original after metadata stripping | Native raster codecs differ; every uploaded variant removes EXIF/GPS/IPTC/XMP and never upscales |
| Tag graphemes | JDK regex grapheme clusters in core:logic | Swift Character; the temporary Android store copy used Android ICU | Keep the shared rule pure JVM; existing emoji/modifier/length fixtures pass, while Unicode tables remain platform supplied |
| Map engine | MapLibre Native (OpenGL ES build, pinned 13.7.1) with OpenFreeMap vector tiles; the fog is a C++ custom layer drawn inside MapLibre's frame | MapKit with a Metal view (`FogMetalVeil`) presented in the same Core Animation transaction | Decided by the fog spike (`docs/fog-spike.md`): no key or billing, and the fog cannot lag behind the map by construction |
| Fog chunks | Fine level 32,768 map point chunks; mid and far levels 2^20 (1,048,576) | 32,768 on every level | A draw call per chunk costs more on GL than on Metal: ~900 chunks per level took 9-11 ms of CPU per zoomed-out frame on the emulator, 9 coarse chunks 0.53-0.56 ms. Float32 inside a coarse chunk stays under a thousandth of a screen point at those zooms. On the iPhone stress seed: fine 274, mid 9, far 9 chunks (iOS sizes: far 267) |
| Fog coverage resolution | Optional half-resolution coverage pass (`FogLook.halfResolutionCoverage`, off by default), sampled bilinearly | Always full resolution, nearest | Fill rate of mid-range GPUs: a quarter of the coverage fragments on an edge that already has a 7-17 point feather. To be decided by GPU timings on real phones |
| Fog scale under rotation | Screen points per map point are the length of the frame's first column | `bounds.width / visibleMapRect.width`, which shrinks when the map is rotated | Keeps the corridor width, the level of detail and the cell size constant while the map turns; equal to iOS without rotation |
| Metres per map point | MapLibre's spherical Web Mercator scale (cos φ × 40,075,016.686 m / 2^28) | `MKMetersPerMapPointAtLatitude` | The scale MapLibre's own map uses; differs by about 0.5 % at 45°, so the 50 m corridor floor, the 300 m and 400 m camera floors and the 150 m reveal radius are metres of the map actually shown |
| Fog frame scheduling | No display link and no rest-frame latch: MapLibre draws on demand and calls the layer inside its frame; a repaint is requested with `MapLibreMap.triggerRepaint` | `CADisplayLink` during gestures, `presentsWithTransaction`, a "rest frame drawn" latch keyed by palette, carve and cells | MapLibre already presents tiles and fog together and draws nothing while the camera rests |
| Fog in the background | `MapView.onStop` pauses MapLibre's GL thread; the layer also skips any frame drawn while suspended; the coverage texture is released on the GL thread before the thread pauses, and on memory trims while it runs | `draw` returns while the app is in the background; the texture is released on a memory warning | GL calls need the context current on MapLibre's thread, which is paused by the time Android 14+ sends its only trims (UI hidden, background) |
| Attribution carve | Not ported | `FogCarveWindow` in the shader, switched off (owner, 26 and 28 September) | MapLibre's logo and attribution are Android views above the map, so the fog never covers them |
| Camera insets | The camera receives the total (safe area plus `MapCameraCommand.Padding.insets`) as MapLibre bounds padding | `setVisibleMapRect(edgePadding:)` adds the map's safe area itself | Same sum on both platforms; MapLibre does not know the window's safe area |
| Unknown-speed dash | MapLibre `line-dasharray` of 6 / width (MapLibre scales dashes by the line width and keeps them in screen units) | `ScreenScaledDashRenderer`, 6 pt dashes | MapLibre never stretches a dash between tile zooms, which is what the iOS renderer fixed for MapKit |
| Route casing on the light mist | White at 0.94 under a route drawn over the mist, `#14141A` at 0.55 over the night fog | `CasedPolylineRenderer` always dark: the trip map with fog was always the dark map | Follows `RouteVeinRenderer.resolvedColors(palette:)`, the rule iOS uses for routes on the paper atlas |
| Map markers | Discs per kind and round photo thumbnails; a chosen place pin grows 1.2× and its name card is an image drawn above it; the suggestion ring is solid | `PlacePinView` (dashed suggestion ring, a label view over the chosen pin), labelled checkpoint cards, photo pins | MapLibre circle strokes cannot be dashed, and a symbol layer cannot hold a view, so the card is drawn as an image |
| RDP simplification | Iterative walk with an explicit stack | Recursive | Same kept indices (tested against the recursion); an eight-hour track is ~29,000 points, too deep for an Android worker thread's stack |
| Text size | `AppType` roles and `inter` keep a fixed size (dp converted to sp); `interScaled` follows the system's non-linear font scale, with no per-style curve | `Font.inter` uses `fixedSize`; `interScaled` follows Dynamic Type relative to a text style | Same adoption by flow as iOS; Android has one scaling curve, and it is non-linear from Android 14 |
| Glass background | `glassBackground()` fills with the theme's translucent glass tint and the hairline border | `.ultraThinMaterial` blurs what lies behind | Compose cannot blur another view's pixels on minSdk 29 without a third-party renderer |
| Symbols | Hand-drawn `AppGlyph` paths on a 24-unit grid; `fill` variants cut their mark out of the disc | SF Symbols | SF Symbols do not exist on Android, and Material icons would be another app's look |
| House dialog | A second tap during the 160 ms exit is ignored; a chosen answer still runs if the dialog is torn down mid-exit; dialogs may stack, so there is no wait queue | `AppConfirmDialog` can run a handler twice on a double tap; `AppDialogPresentation.waitUntilFree` queues covers | The double tap could repeat a deletion; Compose dialogs are windows that can stack, UIKit covers cannot |
| Modal windows | Dialogs and sheets are Compose `Dialog` windows with the platform dim and animation off; the status bar glyphs keep the app theme while one is up | `fullScreenCover` without its transition; the status bar keeps its style | A dialog window decides the glyph colour while it is on top; the default would put white glyphs over the light scrim |
| Action popover | `ActionPopover` closes itself, then runs the row's action; a tap in its shadow margin closes it | Call sites close the popover by hand and wait 260 ms for UIKit before presenting anything | No platform dismissal to wait for; one order for dialog and popover |
| Sheet | House bottom sheet: top radius 28 (`AtlasTheme.sheetRadius`), `AtlasTheme.scrim`, drag down or back to close; the large detent stops 10 dp below the status bar | System sheet with a measured `.height` detent, system dim and grabber area | Android has no system sheet with these detents; the numbers are the app's own sheet tokens |
| Hold press | The hold animation and the long-press gesture both last `max(500 ms, system long-press timeout)` | 0.5 s | Android lets people lengthen long presses in accessibility settings; both halves follow the longer delay |
| Reduce motion | «Remove animations» (animator duration scale 0) | Reduce Motion | The Android setting that asks the same thing |
| Haptics | `Haptics` maps to Compose feedback types: tap ContextClick, action VirtualKey, success Confirm, error Reject, selection SegmentTick, reactions ToggleOn/ToggleOff | UIImpactFeedbackGenerator styles | Android's constants carry meaning rather than strength; the system haptics switch still applies |
| Tab bar gap | `bottomGap` is measured from the top of a tappable system bar (three-button navigation), from the physical bottom otherwise | 22 pt from the physical bottom on every phone | The three-button bar takes taps; gesture navigation matches iOS exactly |
| Touch targets | Small controls (nav circle 40, sheet close 30) receive taps over Compose's automatic 48 dp minimum, layout unchanged | Grown to 44 pt with padding taken back out of layout | Android's minimum touch target |
| Tabs | Each tab keeps its saveable state while another is shown; back on any tab but Лента returns to Лента | Switching tabs recreates the tab's view; no back gesture between tabs | Android bottom navigation and the start-destination back rule |
| Theme change | The palette cross-fades in 280 ms (colour interpolation); system bar glyphs and the window ground follow the in-app theme | `UIView.transition` dissolves a window snapshot; `overrideUserInterfaceStyle` on every window | Compose has no window snapshot dissolve; recreating the activity would lose state |
| Language | Android's per-app language (system from 13, AppCompat below); with nothing chosen the app follows the phone and saves nothing | iOS saves its first detection under `appLanguage` | The system offers the per-app language in Settings, and «System default» there has to stay true until the person picks |
| Location source | Platform `GPS_PROVIDER`, raw fixes every second, no distance filter; idle adds the network provider | CoreLocation `BestForNavigation`, Apple's fusion of GNSS, Wi-Fi and cell | The app runs its own Kalman filter, continuity gate and odometer door on raw input; the fused provider would smooth twice and is missing on phones without Google services. Fewer coarse fixes (65 to 200 m) in tunnels and garages, so straight fills close more gaps |
| Fix time | Phone clock minus the fix's age on the monotonic clock | `CLLocation.timestamp` | GNSS time can differ from the clock every trip date is written with |
| Live Activity | The foreground service's ongoing notification: distance, speed, a chronometer of driving time, Pause/Resume and Finish; a draft shows a «Draft» label; no checkpoint button | Live Activity with a checkpoint button, a separate passive «Recording a trip» notice and an «auto start» notice | One ongoing notification is mandatory for the service anyway; checkpoints during recording come with the checkpoint screens |
| Pause across process death | A recording killed while paused is adopted paused (`RecorderSession` in preferences) | Adopted unpaused | A paused recording keeps an iPhone app alive; Android vendors kill even foreground services |
| Auto-trip memory | Trigger dedup time, «already reminded», last motion end and the connected stereo are kept in preferences | In memory of the long-lived service | Android may start a fresh process for every transition or Bluetooth broadcast |
| Car stereo identity | Saved stereo keyed by Bluetooth address, the name as a fallback | Audio route port name | Names repeat across cars of one brand; the address is what the broadcast carries |
| Android Auto | A local `android-auto` stereo binding; `CarConnection` projection/native events start and stop like a saved Bluetooth stereo in both trigger modes; the link sheet and process/service wakes query the current connection | iOS 0.9.3 links the CarPlay audio-route port name and treats `.carAudio` as a stereo | CarConnection exposes the connection type, without a head-unit identifier. One Android Auto binding therefore covers any connected head unit; broadcasts reach a registered receiver only |
| Stereo snapshot on wake | `AudioManager.GET_DEVICES_OUTPUTS` supplies connected Bluetooth audio outputs, combined with CarConnection | AVAudioSession supplies the current audio route | Android exposes available output ports without starting audio playback; a linked connected output can count even if this app is not playing through it |
| Auto-record wake | Activity Recognition transitions call the shared motion policy; process startup and an idle service restart query live linked Bluetooth/Android Auto outputs, with no automotive signal assumed | Live Core Motion, significant-location wake and background launch query motion history and the current audio route | Android has no CoreLocation significant-change wake or matching Core Motion history query. The delivered IN_VEHICLE transition supplies automotive evidence; a wake without one can start only through the stereo-only policy or a stereo connection event |
| PRO 0.9.3 policy | Pure unknown-storefront read policy and offer-session state in `ProPolicies.kt`, tested without purchase services; no app lifecycle wiring | StoreKit storefront/product refresh and NotificationCenter-driven ProOfferCoordinator | PRO remains hidden at Android launch; StoreKit, catalog reloads and entitlement observers have no Android purchase service to drive |
| Drive start time | The IN_VEHICLE transition's own time backdates the trip | Core Motion history query | Activity Recognition delivers the transition time with the event |
| Motion trigger availability | Needs Google Play services | Core Motion on every iPhone | Android has no platform activity recognition; Bluetooth and Android Auto still trigger |
| Refused background start | The recording is ended and «Recording didn't start» is posted | Not applicable | Android can refuse a background foreground-service start; a recording without its service writes nothing |
| Auto-stop deadline | Coroutine timer while the service keeps the process alive; no scheduled fallback notification | Timer plus a scheduled local notification for a suspended app | The foreground service keeps the process running for the whole recording |
| GPS watchdog | Not ported | Restarts CoreLocation after 30 s without a fix | Android's location manager does not pause updates by itself |
| Untitled trips | Geocoding retried at launch for finished trips only | Retried on network restore, including an unfinished recording | Naming a recording mid-drive is pointless; the network listener comes with the sync work |
| Raw fix journal marks | Only «launch» | launch, background, foreground, terminate | No lifecycle observer in core:location yet |
| Rewards result | `TripRewardsResult` with badge rules | `TripCompletionData` with `Badge` (titles inside) | Words and art are resolved by badge id on the screen |
| Fog on finish | `RevealIngest` hook, no-op until core:map provides it | `RevealedLayerStore.ingest` | The reveal builder belongs to the fog module |
| Android copy | `tools/strings/android.json` supplies all 13 languages for Android-only words and platform wording overrides, merged into the generated design-system resources | Swift localization tables | Android permission names, Google sign-in, Google Play updates and vendor power managers differ. No Android override may fall back to English; hidden PRO copy uses neutral subscription wording |
| Trip screen state | ViewModel and immutable StateFlow projections; worker dispatcher and event flows are injected | ObservableObject, view-owned State and NotificationCenter | Android lifecycle ownership; mutable persistence models and platform map/image objects do not escape into screen state |
| First Mine load | Room is read on the injected worker on every opening, including the first | FeedView can synchronously load the first Mine frame; later loads use fetchTripsAsync | Room forbids database work on the main thread; trip detail still exposes preview metadata before any coroutine runs |
| Trip export handoff | State carries the filename, format and generated text; the platform share adapter writes the temporary file | TripDetailView writes a temporary file and presents the system share sheet | This layer has no composables or Android framework state; file creation and FileProvider sharing belong to the following UI work |
| Journey title and comment Unicode | JDK grapheme matching, Unicode normalization and whitespace tables | Swift Character and Foundation normalization/CharacterSet | Pure JVM rules; the 60-character journey title and 500-character comment limits stay unchanged, with the iOS fixtures retained |
| Presentation lifecycle | AndroidX ViewModel, StateFlow snapshots, injected coroutine dispatcher and Room invalidations; map camera commands have revision acknowledgements | MainActor ObservableObject, Combine and NotificationCenter | Android lifecycle and asynchronous Room reads; revisions prevent an old map acknowledgement consuming a newer command |
| Initial Places snapshot | `loaded=false` until the first Room batch finishes; suggestions remain null until computed | The initial place list is filled synchronously in init | Room cannot fetch on the Android UI thread. The UI must use `loaded` before showing the empty-library screen |
| Local presentation preferences | SharedPreferences string values, including JSON snapshots and the notification pre-mute category list | UserDefaults strings, Data and typed arrays | Android persistence adapter; the iOS raw keys, JSON fields, enum values and category order are preserved |
| Sign-in request | Credential Manager: the button asks `GetSignInWithGoogleOption`; the «sign in again» card first asks `GetGoogleIdOption` limited to accounts that already used the app (auto-select), then every account, then the button's picker | `ASAuthorizationController` with an Apple ID request | Google's guidance for the two entry points; one tap back to the same account after a soft expiry |
| Name at sign-in | Same account: the name kept on the phone; otherwise the server's name, then Google's (clamped to 30), then a generated one | Apple `fullName` first (delivered only on the first authorization), then Keychain, server, generated | Google gives its name on every sign-in; ranked first it would overwrite a name chosen in TripTrack |
| Credential state probe | None; a soft expiry comes only from a rejected refresh token | `getCredentialState` at launch (revoked, notFound, transferred are soft expiries) | Credential Manager has no credential-state API for Google ID tokens |
| Account email | Held in memory from the login answer and `/auth/me`, shown as «Google · a•••@gmail.com»; the account screen re-reads it on every opening | Keychain; «Apple ID · …» | No personal data in preferences that Auto Backup copies; nothing offline needs it |
| Session recovery | A silent refresh that brings a soft-expired session back also orders a sync pass | The next foreground or 300-second timer pass | The queue was paused while the session was dead; without a nudge it waits for the timer |
| Sync engine lifecycle | `SyncHost`: one `SyncEngine` per signed-in account, built after the session is read and closed at a hard sign-out; requests made before it exists wait and are handed over; periodic and immediate work are cancelled when nobody is signed in | One process-wide `SyncQueue`/`SyncCoordinator`, cleared on an account change | The Android queue persists per account on disk; a guest has nothing to wake up for |
| Photo files | Trip and vehicle photo files in `noBackupFilesDir` | Documents, excluded from backup | The Android form of the iOS backup exclusion, and the directory the sync transport reads; the app graph had used `filesDir` |
| Hard sign-out cleanup | Also clears Credential Manager state | No counterpart | Otherwise auto-select could sign the same Google account straight back in |
| Onboarding questions | Location page: precise and approximate together; background page: «all the time» (Android 11+ opens its settings page, and the page says so) then physical activity; notifications only from Android 13; nearby devices not asked | When in use; Always then Motion & Fitness; notifications | Android's permission model; the questions go into the record screen's ledger, so none is asked twice |
| Onboarding example card | Always the drawn example | The newest real trip when there is one | A first run on Android has no trip; the real card needs the share poster projection, not ported yet |
| Account screens | «Account & Sync» is a house sheet with the back chevron, the blocked list a second sheet over it; the blocked list shows a spinner and text-only empty and error states | Sheet with a NavigationStack push; skeleton rows and illustrations | No navigation stack inside a house sheet; the skeleton and illustrations are not ported yet |
| Google button | White button, the Google «G» and «Sign in with Google» in Inter from generated Android-only strings in all 13 languages | Apple's white button with the Apple logo | Google's brand mark on the house button; the words follow the in-app language |
| Precise location | Recording requires `ACCESS_FINE_LOCATION`; approximate access shows an explanation and an app-settings link. Both foreground permissions are requested together. Android 11+ background access explicitly opens app settings and reads the result before asking for physical activity | `MapViewModel.startRecording` blocks denied/restricted authorization; `RealGPSProvider` filters inaccurate fixes. This checkout has no explicit reduced-accuracy request or prompt | Android exposes approximate access as a separate grant and requires both permissions in one request; the task requires an actionable explanation while preserving onboarding progress after refusal |
| Auto-record settings | One `PreferencesAutoRecordSettings` owner in default preferences, read by settings and recording.
